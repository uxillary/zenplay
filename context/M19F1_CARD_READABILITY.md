## Geometry and implementation

The four paths in `cardArtwork.ts` retain a shared 100 × 100 coordinate system and use the same silhouettes for central pips, corner suits and foundation guides. Hearts and diamonds use the existing strong red; clubs and spades now use near-black `#171717` in Classic and `#111111` in High Contrast. A 100px raster area check measured approximately 3,996 filled pixels for hearts, 3,780 for diamonds, 4,038 for clubs and 3,925 for spades. Their filled areas are within about 7% of each other without separate suit-specific scaling. The club centre alpha was 255 at 100, 13 and 7px raster sizes.

The corner remains one rank-and-vector-suit component in `CardView`. Its font and suit size scale with `--zen-card-width`; `10` uses a compact size and tighter tracking. The corner has a white backing, explicit spacing and edge padding. The existing A–10 pip layouts and centre positions remain unchanged. The card width formula and seven-column board are unchanged. Only the court-card index framing changes; the twelve approved J/Q/K SVG illustrations, card backs, themes, rules, saves and other games were not edited.

## Static visual verification

The reproducible [52-card SVG sheet](M19F1_CARD_SHEET.svg) and [1:1 PNG render](M19F1_CARD_SHEET.png) include all four suits and thirteen ranks at 41px (320px viewport equivalent), 47px (360px), 51px (390px), 57px (430px) and 88px (desktop). They also include 41px Large Print and High Contrast sections. The sheet is generated by `node --experimental-strip-types scripts/generate-solitaire-card-sheet.mjs`; it embeds the unchanged court files and renders the current suit paths and pip layouts. The PNG was rasterised at 72 DPI so one SVG unit equals one output pixel.

I inspected the 1:1 render and a [41px mobile detail crop](M19F1_MOBILE_DETAIL.png), including all four 10s and the court indices. In that static render, ranks and corner suits remain separate, no symbol is clipped, dense pip arrangements remain identifiable, and all four suits have similar visual weight. The enlarged crop was used only to inspect the 1:1 pixels. The preview reproduces the component geometry and CSS sizing formula, but is not a browser screenshot of the game.
